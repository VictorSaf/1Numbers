# Consultant AI real — plan de implementare

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consultantul din `/api/ai/consult` vorbește cu Claude prin SDK-ul oficial, ține minte firul conversației, iar când nu are cheie spune limpede că nu e disponibil în loc să inventeze.

**Architecture:** Ruta `server/src/routes/ai.ts` renunță la `fetch` brut, la comutatorul `AI_PROVIDER` și la ramura OpenAI. Rămâne un singur furnizor — Anthropic, prin `@anthropic-ai/sdk` — izolat într-un modul subțire (`server/src/lib/anthropic.ts`), plus un modul pur care compune mesajele (`server/src/lib/consultMessages.ts`) și care se testează fără rețea. Disponibilitatea nu mai e o variabilă de mediu cu trei valori, ci un singur fapt verificabil: există sau nu `ANTHROPIC_API_KEY`. Istoricul conversației trăiește în starea componentei și se retrimite la fiecare rundă, fiindcă API-ul e stateless; profilul numerologic se așază înaintea punctului de cache, ca să nu se plătească din nou la fiecare întrebare.

**Tech Stack:** Express 5 + TypeScript + zod + vitest/supertest pe server; React 18 + Vite 6 + Vitest pe frontend; `@anthropic-ai/sdk`.

**Spec:** nu există un document de spec separat. Diagnosticul care generează planul e verificat direct în cod și rezumat în secțiunea „Diagnostic" de mai jos; aceasta ține locul specului, iar executantul citește ambele.

## Decizii, cu argumentul lor

### D1. Modelul: `claude-opus-5`

Skill-ul `claude-api` este explicit: *„ALWAYS use `claude-opus-5` unless the user explicitly names a different model. […] Never downgrade for cost — that's the user's decision, not yours."* Tabelul „Current Models" din același skill îl dă la $5 / 1M tokeni intrare și $25 / 1M ieșire, cu fereastră de 1M.

Argumentul de calitate, nu de cost: sarcina consultantului nu e aritmetică — numerele sunt deja calculate în `src/lib/numerology.ts` și ajung gata calculate în prompt. Sarcina e **interpretare în proză, în trei limbi, dintre care două nu sunt engleza**, cu instrucțiuni de stil și de limitare (fără predicții definitive, fără sfaturi medicale sau financiare) pe care modelul trebuie să le respecte fără să fie reamintit. Aici diferența dintre nivele se vede în calitatea limbii române și ruse și în disciplina față de limitări — exact zonele în care modelul de sus se desparte de restul.

**Dacă Victor vrea mai ieftin**, alternativa e `claude-sonnet-5` ($2 / $10 — 2,5× mai ieftin la intrare, 2,5× la ieșire). Ce se pierde, spus direct: proză mai puțin nuanțată în RO și RU, și o aderență mai slabă la clauza de limitare — adică riscul crescut ca modelul să alunece în predicții categorice, exact ce promptul îi interzice. Nu recomand schimbarea fără a compara răspunsurile pe aceleași cinci întrebări din `FREQUENT_QUESTIONS`. Decizia e a lui Victor; codul o face printr-o constantă într-un singur loc (`server/src/lib/anthropic.ts`).

`output_config: { effort: 'low' }`. Argument: gândirea e pornită implicit pe Opus 5 (skill-ul o spune explicit — omiterea parametrului `thinking` rulează adaptiv), iar `low` e nivelul potrivit pentru „sarcini simple". Interpretarea unui profil deja calculat este o sarcină simplă: nu se descoperă nimic, se explică. `high` (implicitul) ar plăti tokeni de gândire pentru o sarcină care nu are ce descoperi. Dacă răspunsurile ies superficiale, `medium` e pasul următor, într-o singură linie.

`max_tokens: 4000`, fără streaming. Skill-ul recomandă ~16000 pentru cereri non-streaming, „only go lower when you have a hard reason: […] deliberately short outputs". Aici motivul e explicit în promptul de sistem, în toate trei limbile: *„Evită răspunsurile prea lungi sau vagi"*. 4000 lasă loc unui răspuns bogat și taie o buclă scăpată de sub control. Serverul verifică `stop_reason === 'max_tokens'` și, în acel caz, marchează răspunsul ca trunchiat în loc să-l dea drept complet.

### D2. Lipsa cheii = indisponibil, vizibil

Astăzi lipsa cheii duce la `mock`, în tăcere, și interfața arată text inventat ca și cum ar fi real. E cel mai grav lucru din fișier, fiindcă utilizatorul nu are cum să afle.

Planul scoate comutatorul cu trei valori. Rămâne un fapt: `process.env.ANTHROPIC_API_KEY` există sau nu.

- Nu există → ruta întoarce **`503`** cu `{ error: 'ai_unavailable' }`. Nu 500: nu e o eroare, e o stare cunoscută a serviciului.
- Frontendul tratează 503 ca stare distinctă: afișează `t.aiConsultant.unavailable` + `t.aiConsultant.unavailableHint`, dezactivează câmpul de întrebare, **nu adaugă niciun mesaj de asistent în conversație**.
- `generateLocalResponse` se șterge din componentă. Al doilea strat de fabricație dispare odată cu primul.

**Mock-ul rămâne doar pentru teste, marcat ca atare.** Nu ca ramură în rută — ca `vi.mock('@anthropic-ai/sdk', ...)` în fișierele de test, adică exact la granița SDK-ului. Un mock care nu există în codul de producție nu poate fi pornit din greșeală în producție.

### D3. Unde trăiește istoricul: în starea componentei

API-ul e stateless, deci istoricul se retrimite la fiecare rundă, indiferent unde e ținut. Întrebarea e doar dacă îl persistăm.

**Decizie: nu îl persistăm.** Rămâne în `useState` din `AIConsultant`, cum e deja, și se pierde la reîmprospătarea paginii.

Argument:
- Persistența cere o migrație (`010`), un tabel, rute de citire/ștergere și un ecran de administrare. Întrebările unui om despre viața lui sunt date personale — un tabel care le ține fără un buton de ștergere e o datorie, nu o funcție.
- Valoarea întrebării de continuare e *în sesiune*: „și ce înseamnă asta pentru cariera mea?" e util imediat după răspuns, nu peste trei zile.
- Costul de a nu persista e o singură apăsare de buton pierdută. Costul de a persista prost e permanent.

Dacă utilizatorii cer să-și regăsească conversațiile, se adaugă atunci, cu tabel și ștergere, ca proiect separat.

**Creșterea costului pe rundă și cum e tratată:**
1. **Plafon pe istoric.** Schema acceptă cel mult **8 mesaje** (4 schimburi) × maximum **1500 caractere** fiecare. Azi e `.max(20)` × 2000, adică de aproape trei ori mai mult. Componenta trimite ultimele 8, nu tot firul.
2. **Se elimină trimiterea dublă.** `buildAIPrompt` nu mai împachetează istoricul în textul întrebării (constatarea 6 din diagnostic). Se trimite o singură dată, în `conversationHistory`.
3. **Cache pe prefixul stabil.** Profilul numerologic — cam 600-900 de tokeni care nu se schimbă în timpul conversației — se așază ca **primul mesaj**, cu `cache_control: { type: 'ephemeral' }`. Ce urmează (istoric + întrebare) crește după punctul de cache, deci nu îl invalidează. Skill-ul e clar: ordinea de randare e `tools` → `system` → `messages`, iar ce e stabil stă înainte de punctul de întrerupere.

**De ce profilul NU merge în `system`, deși acolo ar fi cel mai natural de cache-uit:** fiindcă textul profilului vine de la client. A-l pune în `system` ar însemna să lăsăm clientul să scrie în promptul de sistem — exact gaura pe care comentariul de la `ai.ts:158-164` a închis-o. Profilul merge în `messages[0]`, rol `user`, într-un plic delimitat `<profil_numerologic>…</profil_numerologic>`, ca **date**, nu ca instrucțiuni. Cache-ul funcționează la fel de bine pe `messages[0]`; proprietatea de securitate rămâne.

**Onestitate despre cache:** skill-ul spune că prefixul minim cache-abil e dependent de model, între 512 și 4096 de tokeni, și că sub prag *cache-ul pur și simplu nu se activează, în tăcere*. `system` (~250) + profil (~600-900) poate cădea sub prag pe Opus 5. De aceea Task 3 pune o verificare: se logează `usage.cache_read_input_tokens` și `usage.cache_creation_input_tokens`. Dacă rămân zero, cache-ul nu s-a prins — nimic nu se strică, doar nu se economisește. Nu construim nimic peste presupunerea că merge.

### D4. Limite

**Pe utilizator, nu doar pe IP.** `ipRateLimit` protejează împotriva unei singure adrese; un cont folosit de pe patru rețele îl ocolește. Se adaugă `userRateLimit`, cheie pe `req.userId`.

**Se extinde, nu se duplică:** algoritmul ferestrei glisante din `ipRateLimit.ts` se extrage într-o funcție `slidingWindow(options, keyOf)`, iar `ipRateLimit` și `userRateLimit` devin două apeluri ale ei, în același fișier. O singură implementare, două chei.

**De ce nu `rateLimit.ts` (cel pe abonament):** face 2-3 interogări în bază la fiecare cerere și, la eroare, cheamă `next()` — lasă cererea să treacă. Pe o rută care cheltuie bani reali, fail-open e o decizie greșită. `slidingWindow` refuză determinist, fără bază de date.

Valori: **15 cereri / oră / utilizator**, în spatele celor 30 / oră / IP care există deja. 15 e generos pentru un om care pune întrebări și strâns pentru o buclă scăpată.

**Lungimea întrebării.** Azi există un singur câmp, `userPrompt`, cu `.max(8000)` — care amestecă profilul (lung, generat de noi) cu întrebarea (scurtă, scrisă de om). Se sparge în două: `profileContext` `.max(6000)` și `question` `.max(1000)`. Un om nu scrie o întrebare de 8000 de caractere; opt mii de caractere într-un câmp de întrebare sunt o încercare de a folosi cheia noastră pentru altceva.

### D5. Unde apare consultantul

Azi: doar `/raport` (`src/pages/Premium.tsx`). E pagina de prețuri. Întrebarea pe care și-o pune omul acolo e „merită să plătesc?", nu „ce înseamnă numărul meu?". Consultantul e acolo ca vitrină, nu ca unealtă.

În plus, componenta citește `useProfile()` — profilul activ — deci pe pagina profilului contextul de pe ecran și contextul din prompt sunt același lucru; omul vede la ce se uită modelul.

import Anthropic from '@anthropic-ai/sdk';

/**
 * Singurul loc din server care știe de SDK-ul Anthropic.
 *
 * Nu există comutator de furnizor. Furnizorul e Anthropic; ce variază e dacă
 * avem sau nu cheia. Vechiul `AI_PROVIDER` avea implicit valoarea 'mock', ceea
 * ce însemna că un server fără cheie întorcea text inventat ca și cum ar fi
 * fost răspunsul modelului. Aici, fără cheie, nu se răspunde deloc.
 */

/**
 * Ales pe criteriul calității răspunsului, nu al costului: sarcina e
 * interpretare în proză în trei limbi, cu limitări de respectat, nu aritmetică
 * -- numerele vin deja calculate în prompt. Vezi D1 din planul de implementare
 * pentru ce se pierde la un model mai ieftin.
 */
export const CONSULT_MODEL = 'claude-opus-5';

/** Promptul cere explicit răspunsuri scurte; 4000 lasă loc și taie o buclă. */
const MAX_TOKENS = 4000;

export class AiUnavailableError extends Error {
  constructor() {
    super('ANTHROPIC_API_KEY is not configured');
    this.name = 'AiUnavailableError';
  }
}

export interface ConsultUsage {
  inputTokens: number;
  outputTokens: number;
  cacheReadTokens: number;
  cacheCreationTokens: number;
}

export interface ConsultResult {
  text: string;
  truncated: boolean;
  usage: ConsultUsage;
}

// Citit leneș, la fiecare apel: procesul poate porni fără cheie, iar testele o
// pun și o scot între cazuri.
const apiKey = (): string | undefined => process.env.ANTHROPIC_API_KEY || undefined;

export const isAiConfigured = (): boolean => Boolean(apiKey());

let client: Anthropic | null = null;

const getClient = (): Anthropic => {
  const key = apiKey();
  if (!key) throw new AiUnavailableError();
  if (!client) client = new Anthropic({ apiKey: key });
  return client;
};

export async function askConsultant(input: {
  system: Anthropic.TextBlockParam[];
  messages: Anthropic.MessageParam[];
}): Promise<ConsultResult> {
  const anthropic = getClient();

  const response = await anthropic.messages.create({
    model: CONSULT_MODEL,
    max_tokens: MAX_TOKENS,
    // Gândirea e pornită implicit pe acest model. `low` fiindcă numerele sunt
    // deja calculate: modelul explică, nu descoperă.
    output_config: { effort: 'low' },
    system: input.system,
    messages: input.messages,
  });

  const text = response.content
    .filter((block): block is Anthropic.TextBlock => block.type === 'text')
    .map((block) => block.text)
    .join('');

  return {
    text,
    truncated: response.stop_reason === 'max_tokens',
    usage: {
      inputTokens: response.usage.input_tokens,
      outputTokens: response.usage.output_tokens,
      cacheReadTokens: response.usage.cache_read_input_tokens ?? 0,
      cacheCreationTokens: response.usage.cache_creation_input_tokens ?? 0,
    },
  };
}

```ts
import Anthropic from '@anthropic-ai/sdk';
import { SYSTEM_PROMPTS, SCOPE_CLAUSE, Lang } from './aiPrompts';

export type ConsultTurn = { role: 'user' | 'assistant'; content: string };

/**
 * Compune cererea. Funcție pură: fără rețea, fără mediu, fără bază de date.
 *
 * Două decizii merită spuse aici, fiindcă nu se citesc din cod:
 *
 * 1. Profilul NU merge în `system`, deși acolo ar fi cel mai natural loc pentru
 *    un prefix stabil. Textul profilului vine de la client, iar `system` e
 *    câmpul pe care routes/ai.ts l-a închis tocmai ca să nu poată clientul
 *    îndrepta modelul spre altă sarcină. Merge în primul mesaj, ca date, într-un
 *    plic delimitat.
 *
 * 2. Punctul de cache stă pe profil, adică pe singurul lucru care nu se schimbă
 *    în timpul unei conversații. Ordinea de randare fiind tools -> system ->
 *    messages, tot ce urmează (istoric, întrebare) crește după punct și nu-l
 *    invalidează.
 */
export function buildConsultMessages(input: {
  language: Lang;
  profileContext: string;
  history: ConsultTurn[];
  question: string;
}): { system: Anthropic.TextBlockParam[]; messages: Anthropic.MessageParam[] } {
  const { language, profileContext, history, question } = input;

  const system: Anthropic.TextBlockParam[] = [
    { type: 'text', text: `${SYSTEM_PROMPTS[language]}\n\n${SCOPE_CLAUSE[language]}` },
  ];

  const messages: Anthropic.MessageParam[] = [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: `<profil_numerologic>\n${profileContext}\n</profil_numerologic>`,
          cache_control: { type: 'ephemeral' },
        },
      ],
    },
    ...history.map((turn) => ({ role: turn.role, content: turn.content })),
    { role: 'user' as const, content: question },
  ];

  return { system, messages };
}
```

```ts
import { Request, Response, NextFunction } from 'express';

/**
 * Fereastră glisantă în memorie, cu două chei posibile: adresa clientului sau
 * utilizatorul autentificat.
 *
 * Limita pe IP nu poate proteja un cont folosit de pe mai multe rețele, iar
 * limita pe utilizator nu poate proteja rutele neautentificate (înregistrare,
 * autentificare). Sunt două chei peste același algoritm, nu doi algoritmi.
 *
 * Pentru rutele care cheltuie bani la un furnizor extern se pun amândouă.
 *
 * Starea e per-proces și dispare la repornire, ceea ce e acceptabil aici:
 * apără un deployment cu o singură instanță de abuz ocazional, nu de un atac
 * distribuit. Un depozit comun ar fi necesar dacă API-ul e vreodată scalat.
 *
 * Nu există fail-open: middleware-ul din rateLimit.ts cheamă next() la eroare,
 * ceea ce pe o rută care plătește tokeni ar fi decizia greșită. Aici nu e nimic
 * care să poată eșua.
 */
interface Options {
  windowMs: number;
  max: number;
}

/** Cererile autentificate poartă userId, pus de authenticateToken. */
type MaybeAuthed = Request & { userId?: string };

const clientIp = (req: Request): string => {
  // Every request arrives through the Cloudflare Tunnel, which sets this header;
  // req.ip would otherwise be the loopback address for all callers alike.
  const cf = req.headers['cf-connecting-ip'];
  if (typeof cf === 'string' && cf) return cf;
  const xff = req.headers['x-forwarded-for'];
  if (typeof xff === 'string' && xff) return xff.split(',')[0].trim();
  return req.ip ?? 'unknown';
};

const slidingWindow = (
  { windowMs, max }: Options,
  keyOf: (req: MaybeAuthed) => string | undefined,
) => {
  const hits = new Map<string, number[]>();

  return (req: MaybeAuthed, res: Response, next: NextFunction) => {
    const now = Date.now();
    const key = keyOf(req);

    // Fără cheie nu se numără. Pentru varianta pe utilizator asta înseamnă o
    // cerere neautentificată, pe care authenticateToken a oprit-o deja.
    if (!key) return next();

    const recent = (hits.get(key) ?? []).filter((t) => now - t < windowMs);

    if (recent.length >= max) {
      const retryAfter = Math.ceil((windowMs - (now - recent[0])) / 1000);
      res.setHeader('Retry-After', String(retryAfter));
      return res.status(429).json({ error: 'Too many requests', retryAfter });
    }

    recent.push(now);
    hits.set(key, recent);

    // Opportunistic cleanup so the map cannot grow without bound.
    if (hits.size > 5000) {
      for (const [k, v] of hits) {
        if (v.every((t) => now - t >= windowMs)) hits.delete(k);
      }
    }

    next();
  };
};

export const ipRateLimit = (options: Options) => slidingWindow(options, clientIp);

export const userRateLimit = (options: Options) => slidingWindow(options, (req) => req.userId);
```
